# bazis-statusy 2.4.0

Requires Bazis 2.4.

## Security

- **An update could set any status, bypassing the transitions** (their validators, hooks
  and permissions): the UPDATE schema of `StatusyRouteSetBase` accepted `status` (`PATCH`
  of the item and of `/relationships/status`). The status is no longer in the UPDATE
  schema; it changes only through the transit endpoint. The same holds for `status_author`
  (who changed the status), which was writable on create and update.

## Breaking

- A `PATCH` of an item that sends `status` (or `status_author`) answers 200 and leaves it
  unchanged (fields outside the schema are ignored); `PATCH /relationships/status` is 403.
  Change the status with `POST /{item_id}/transit/`.

## Tools and AI agents

- The package ships `AGENTS.md` (setup of statuses and transitions, the transit API, the
  permissions by status and the rules) and `bazis_manifest.toml` for tools and AI agents
  (see `docs/agents.md` of Bazis).
- New system check `statusy.W001` (`manage.py bazis_doctor`): a JSON:API route that changes items of a
  `StatusyMixin` model does not inherit `StatusyRouteSetBase`, so it has no transit
  endpoint and does not apply the permissions by status.
- `AGENTS.md` documents that the CREATE schema accepts an initial status, to be restricted
  with `add` permissions by status or excluded.
