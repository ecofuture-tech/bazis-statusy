# bazis-statusy 2.5.0

Requires bazis 2.4.2 and bazis-permit 2.4.1; the restriction of `status_aggs` takes
effect with bazis 2.9.

## Security

- **`status_aggs` counted the objects with a filter the list does not allow.** It applied
  the filter of the request (without `status`) with the deprecated `Filtering.qs_apply`,
  which is not restricted by the query scope of Bazis 2.9: a filter through a relation
  counted the objects related to the objects the user cannot see, and `$search` searched
  every text field of the model instead of the search fields of the route, so the counts
  told what the list hides. It now applies the filter with the filtering service of the
  route (`self.inject.filtering`), as the list does: with Bazis 2.9 the counts reach only
  the fields of the LIST schema of the route and the related objects the user can see, and
  a filter the list rejects is 400 `ERR_FILTER`. The filter context has the route, as for
  the list.

## Fixes

- **The routes of the child models failed for a user with permissions on them.**
  `StatusyChildMixin` was not a permission model (`PermitModelMixin`) although its route
  (`StatusySimpleRouteSetBase`) is a permit route: as soon as the user had a permission on
  a child model, its list and items, the `included` child objects of a parent and (with
  Bazis 2.9) a filter through a relation into them failed with `AttributeError`
  (`perms_item_apply`, `get_selector_model`). `StatusyChildMixin` now inherits
  `PermitModelMixin` as `StatusyMixin` does: the child objects are restricted by the
  permissions of the user, with selectors (`author`) and the status of the parent. The
  mixin is abstract and adds no field (no migration).
