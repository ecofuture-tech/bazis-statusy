# bazis-statusy 2.10.0

## Changes

- **A transit of a parent needs no permission of its children.** A transit with
  `is_schema_validate` (the default) validates the children of the item
  (`StatusyChildMixin`) with the transit schema of their route. The schema was built with
  the access check of bazis-permit, so the user also needed a `transit` item permission
  of every child model (`shop.order_item.item.transit.order__author.draft.submit` beside
  `shop.order.item.transit.author.draft.submit`), else the transit of the parent answered
  403 `Permission denied: check access` without naming the child. The children are now
  validated with the field permissions of the user for the transits of their model (the
  restrictions such as `shop.order_item.field.transit.all.all.price.notnull` still apply,
  a failure is 422); the permission of the transit is the one of the parent, checked by
  the transit endpoint as before. Every child is validated, also one the user does not
  view; its errors do not disclose it: the children the user does not view that are
  invalid answer one error 422 `ERR_TRANSIT_CHILDREN_INVALID` (`Some related items are
  not valid for this transit`, translated) without their ids, types or fields, while an
  invalid child he views answers the errors of its fields as before.

## Upgrading

The `transit` item permissions of the child models granted only for the transits of their
parents can be removed from `roles.py`; they are not needed any more (they still open
`GET /{item_id}/schema_transit/` of the child route). A project that used them to forbid a
transit by the children (a user may transit the parent only if he may "transit" every
child) checks it in a validator of the transit instead.
