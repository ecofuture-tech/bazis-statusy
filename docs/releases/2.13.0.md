# bazis-statusy 2.13.0

Requires bazis 2.16 and bazis-permit 2.11 (unchanged).

## Breaking changes

- **On a route set whose `action_transit` is not public, an anonymous user gets no transit,
  neither in `state_actions` nor in `for_transit`.** `state_actions` (and `allow_transits`)
  listed the transits of the roles for anonymous users there, which the transit of the
  route set refuses with 403. A route set that declares the transit `public=True`
  (`route_declare(StatusyRouteSetBase.action_transit, public=True)`) gives them, as its
  transit accepts them. Both metas list exactly what `POST /{item_id}/transit/` of the
  route set takes, without the validators.

## Changes

- **The meta `for_transit` of a list** (`StatusyRouteSetBase`): the transits the user may make
  on each object of the page, by its id, `{"<pk>": ["<transit id>", ...]}` (the ids sorted,
  an object without a transit left out). They are `allow_transits` of the item, what the
  transit endpoint of the route set accepts: the transit permissions whose selector and
  status the object matches, that start from its status. It lists the child transits of a
  `TransitRelation` too; `state_actions` of the item shows them nested under their parent.
  The validators are not called: a transit listed may still be refused with 422, and
  `state_actions` of the item keeps their `restricts`. It costs one query per condition of
  the transit permissions of the role that can give a transit from a status of the page
  (plus the page and the transits of the model), not one per object, and nothing for a
  user without a transit permission; it is computed only when the request names it
  (`?meta=for_transit`). A board shows the transits of its cards by it, instead of reading
  `state_actions` of each card.
