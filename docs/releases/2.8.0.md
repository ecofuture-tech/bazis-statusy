# bazis-statusy 2.8.0

## Fixes

- **The lazy titles of the payload fields are strings in the JSON schemas of the payload.**
  `Field(title=_('...'))` (and a lazy `description`) of a payload model was copied by
  pydantic into the JSON schema as the lazy object: the schema of
  `item.transit_payload_type(transit)` was not a JSON document (the contract export of
  bazis-front failed on it, a trial project wrapped the titles with `str()` at import, in
  the language of the process start), and `model_dump_json()` of the state action failed.
  The payload type of a transit and the body of the transit endpoint now generate their
  JSON schemas with the lazy texts translated in the active language, at each generation,
  as the schemas of the core (2.8): `state_actions` in the language of the request, the
  contract in the language of its export.
- **No `PydanticDeprecatedSince211` warning when building `state_actions`**: the default
  `code` of a state action is read from the class (`model_fields` of an instance is
  deprecated since Pydantic 2.11).
- The validator of the sample returns early for `payload_validate_none`, as the guide
  says: `state_actions` of an item with that transit failed with `AttributeError`.

## Documentation

- The guide describes the signatures of validators and actions (`(self, transit, user,
  payload)`, `(self, statusy_transit, payload)`), what a before action may return, where
  the payload type comes from (the annotations of `payload` of all the methods of the
  transit, combined into one model), the transit request body, `StatusyContentType` in
  a data migration and the titles of the payload fields.

## Compatibility

- The payload type of a transit also inherits `TranslatedSchemaModel`
  (`bazis.contrib.statusy.schemas`), after the payload models, and
  `TransitActionEndpointBodySchema` is a `TranslatedSchemaModel`: their
  `model_json_schema()` uses `TranslatedJsonSchema` unless a `schema_generator` is passed.
