# bazis-statusy 2.3.0

Requires Bazis 2.3 (Django 6.1, FastAPI 0.142) and bazis-permit 2.3.

- The default status is computed for every created object, and each time it inspected the
  database catalog (the table list and the columns of the statuses) before
  `get_or_create`: four queries per created object. The catalog is now inspected once per
  process.
- A new transition without an id looked up the existing ids with an empty prefix (all
  transitions) instead of its own prefix.
- Migration `0006_transits_related_through`: the migrations did not match the model
  (`makemigrations` created a migration inside the installed package); the database does
  not change.
- `HTTP_422_UNPROCESSABLE_CONTENT` replaces the deprecated Starlette constant; lint errors
  fixed.
- Dependencies: `bazis>=2.3.0`, `bazis-permit>=2.3.0` (with its fixes: related objects check,
  permission cache invalidation, anonymous selectors, 422 with sparse fieldsets).
- CI runs the tests on Python 3.12–3.14 and with the lowest allowed dependency versions and
  checks for missing migrations; releases are made with the Release workflow
  (see `CLAUDE.md`).
