# bazis-statusy 2.7.0

## Breaking changes

- **`transit_apply` makes only a transit that starts from the current status of the
  item.** In code (`item.transit_apply(transit, user, payload)`, a task, a hook, the
  partial of `@transit_link`) it applied any transit of the model: a transit that starts
  from another status set its target status anyway, wrote its history record and ran its
  actions, past the workflow the transits describe. It
  fails now, before the validators and without writing anything, with the error of the
  transit endpoint for a transit the item does not have: `JsonApiBazisException` with a
  `TransitError` (`ERR_TRANSIT`, status 400, the item in `item`). The transit endpoint
  answers as before (403 when the transit is not among the allowed ones of the item). A
  transit of the system takes its transit with `item.get_transit('<id>')`, which is None
  in another status, or catches the error; `@transit_link` already returned only the
  transits of the current status.
